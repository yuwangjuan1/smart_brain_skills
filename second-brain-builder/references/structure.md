# 目录结构规范

第二大脑的目录不是分类学，是**工作流**——目录结构应该跟着"信息怎么进来、怎么被使用"走，而不是追求分类完美。

## 方案 A：最小可用版（4 个顶层目录）

适合刚起步、每天只能投入 10 分钟以内的用户：

```
vault/
├── 00-HOME/          # 入口：总索引 + 每周整理清单
├── 10-收件箱/         # 一切未处理信息的唯一入口
├── 20-笔记/           # 处理后的正式笔记（按主题平铺，不建深层子目录）
└── 90-归档/           # 不再活跃但不想删的内容
```

核心纪律：**收件箱每周清空一次**，清空的动作就是把有价值的笔记移到 `20-笔记` 并加好 frontmatter。

## 方案 B：标准版（7 个顶层目录）

适合长期经营、多领域学习/创作的用户：

```
vault/
├── 00-HOME/           # 总入口：导航页、执行清单、年度目标
├── 10-收件箱/          # 未处理信息
├── 20-领域/            # 正在深耕的知识领域（每个领域一个"领域包"）
├── 30-项目/            # 有明确终点的事（做完归档）
├── 40-创作/            # 对外输出：文章、视频脚本、教程
├── 50-复盘/            # 错题集、周报月报、决策记录
└── 90-归档/            # 冷却区
```

数字前缀的作用：固定排序，让高频目录永远排在最上面；也预留了插入空间（比如以后想加 `35-模板`）。

## 方案 C：创作驱动版

在标准版基础上，把 `40-创作` 拆细，适合内容创作者：

```
40-创作/
├── 选题库/             # 所有灵感先到这里
├── 草稿区/             # 正在写的
├── 已发布/             # 按 platform-日期-标题 命名
└── 数据复盘/           # 发布后的数据与复盘
```

## 命名约定

| 对象 | 约定 | 示例 |
|---|---|---|
| 目录 | `NN-中文名` | `20-领域` |
| 笔记文件 | 不含特殊字符 `\/:*?"<>|`，用连字符 | `2026-10-13-损失厌恶.md` |
| 带日期笔记 | `YYYY-MM-DD-标题`，日期是创建日 | `2026-10-13-周复盘.md` |
| 索引页 | 与目录同名或叫 `INDEX` | `00-HOME/HOME.md` |

## 每日执行清单机制（第 5 节）

在 `00-HOME` 建一张 `执行清单.md`，分三档：

```markdown
# 每日执行清单

## 每日（5 分钟）
- [ ] 灵感/待办丢进 10-收件箱，不用管格式
- [ ] 今天学到的最重要的一件事，一句话记下

## 每周（10 分钟）
- [ ] 清空收件箱：有价值的移入 20-笔记，加 frontmatter
- [ ] 检查 50-复盘：本周有没有值得记的"错题"
- [ ] 更新 HOME 页的"最近修改"区

## 每季（30 分钟）
- [ ] 90-归档里翻一遍，确认没有放错的内容
- [ ] 回顾领域包进度，决定下一季深耕什么
```

## 反模式（不要这样做）

1. **不要建超过 2 层的目录深度**——深层目录 = 埋葬
2. **不要追求一次分类到位**——分类会过时，搜索 + 链接才是检索主力
3. **不要用颜色/图标当主要组织手段**——三天就维护不动了
4. **不要收藏代替阅读**——剪藏进收件箱 ≠ 学会了
