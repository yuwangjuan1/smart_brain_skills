# 领域包建设流程（D2）

领域包是"对某个领域的系统化深耕"：不是一堆笔记的堆放处，而是一个**有索引、有书单、有主题页、有著作骨架、有技能包、有错题集的完整作战单元**。适合你想真正吃透的领域（比如投资心理学、Prompt 工程、某个技术栈）。

## 判断：什么领域值得建领域包

三个条件满足两个再建：

1. 未来 1 年以上会持续接触
2. 有经典著作/系统知识存在（不是纯碎片信息）
3. 你需要对外输出（教学、创作、决策）——有输出压力才有整理动力

不满足就先放 `20-笔记` 平铺，不要过早建包。

## 领域包结构（七件套）

```
20-领域/投资心理学/
├── INDEX.md            # ① 索引页：全包导航 + 当前进度
├── 领域观.md            # ② 我对这个领域的核心理解（一页纸）
├── 书单.md             # ③ 经典著作清单 + 阅读状态
├── 主题页/             # ④ 按主题组织的结构化笔记
│   ├── 损失厌恶.md
│   └── 锚定效应.md
├── 著作骨架/           # ⑤ 每本经典一本书架：核心论点 + 章节骨架 + 金句
├── 技能包.md           # ⑥ 该领域的实操技能清单（可检验的动作）
└── 错题集.md           # ⑦ 我在这个领域踩过的坑
```

## 建设五步（D2 流程）

### D2-1 定边界

用一句话写清"这个领域管什么、不管什么"，放进 `领域观.md`。例：投资心理学管"决策时的心理偏差"，不管"估值技术"。

### D2-2 列书单

三类书目配比（参考）：

- **经典**（3-5 本）：领域公认的奠基之作
- **现代**（3-5 本）：近十年整合者写的畅销佳作
- **实践**（1-3 本）：手册/案例类，供翻查

每本标注状态：`想读 /在读/读过/反复读`。

### D2-3 搭主题页骨架

先凭现有认知列出 5-9 个主题（太少说明领域太窄，太多说明还没抓住主干），每个主题一页。**先写"我目前的理解"，哪怕全是错的**——后面的阅读就是不断修正这些页面的过程。

### D2-4 读书建骨架

每读完一本书，建一张著作骨架页，固定格式：

```markdown
# 《书名》骨架

- **核心论点**：一句话
- **章节骨架**：每章一行摘要
- **对我最有用的 3 个点**：链接到相关主题页 [[损失厌恶]]
- **我不同意的地方**：书上观点也要过脑子
```

### D2-5 用起来 + 回流

- 对外输出（文章/分享/决策）时强制引用领域包内容
- 输出中发现讲不清楚的地方 → 回流成新的主题页或错题
- 每季度在 `INDEX.md` 更新一次领域包进度

## 领域包的健康信号

| 信号 | 健康 | 不健康 |
|---|---|---|
| 主题页 | 有"我自己的话" | 全是摘抄 |
| 著作骨架 | 有关联链接、有反驳 | 孤立的读书笔记 |
| 错题集 | 在增长 | 空的（说明没在实战） |
| INDEX | 每季度在动 | 建完就死 |

## 反模式

1. **不要一上来建 5 个领域包**——一个季度养熟一个就是胜利
2. **不要先读完书再建包**——包和读是同步的，包就是读书的草稿纸
3. **不要追求主题页完美**——`seedling` 状态的粗糙页面好过空白
